# OUT_OF_SCOPE — openviking-adopt plan

Agnostic-spec capture of things observed while working this plan but not acted on (MASTER_PLAN
§4.3). WHAT + WHY, never HOW — no prescribed solution, no code excerpts. Always-writeable
regardless of scope. Reviewed at scope-closing checkpoints: each entry gets promoted into
SCOPE.md, escalated into INVENTORY.md, archived as won't-fix, or deferred forward.

Format per entry: date · area/file · one-line problem · severity guess · next-touch pointer.

---

- **2026-09-21 · Obsidian vault decision surfaces (`lib/obsidian-{decision-notes,session-notes,summarizer,link-checker}.mjs`)** · Block 3 excludes superseded decisions from recall (injector, decision-FTS channel) and from MEMORY.md, but the vault note generators still list every decision row, so a superseded decision keeps a note beside its successor. · Severity: low (browsing surface only; recall is correct) · Next touch: a small follow-up that renders supersession in the decision note (a "superseded by [[…]]" line) rather than hiding the row.
- **2026-09-21 · `memory.extracted` event payload** · The flush result now carries the typed-merge counts (`entities_new`, `aliases_resolved`, `decisions_superseded`, `known_entities`), but `workspace-bin/memory-daemon.mjs` `emitExtractEvent` copies named fields only and `packages/event-schemas` does not declare them, so the watcher cannot see them yet. Step 3.2's runtime Verify therefore reads the tables, not the event. · Severity: low · Next touch: extend the event schema + emitter in a schema-bump step.
- **2026-09-21 · consolidation archive vs aliases** · When consolidation archives an entity (`entities_archived`) its `entity_aliases` rows are cascade-deleted (FK ON DELETE CASCADE), so a resurrected entity comes back without its aliases. · Severity: low · Next touch: archive aliases alongside the entity in `lib/consolidation.mjs` when Block 3 closes on the node.
- **2026-09-21 · LoCoMo memory-quality benchmark** · The review recommended running LoCoMo against the inject server; OpenViking's `benchmark/` harness is under its AGPL root. Needs a live LLM + embedder, so it cannot run in the authoring container. · Severity: medium (no memory-quality baseline exists) · Next touch: a separately scoped benchmark step on the node, with a license check on any reused harness code.
- **2026-09-21 · gateway config (`~/.openclaw/openclaw.json`) vs OpenClaw 2026.5.27** · `channels.telegram.streaming` and `channels.discord.streaming` are scalars (`partial`, `off`) where the installed gateway requires objects, and `tools.web.search.apiKey` sits under a legacy key; the gateway rejects the file at startup and launchd has re-spawned it 46,549 times (exit 1, 10 s throttle), so no Telegram/Discord channel has been up for days and `openclaw config set` refuses to write — step 4.1 cannot set `plugins.slots.contextEngine` until the config is migrated. `openclaw doctor` previews the migration; applying it brings the channels back online, which is an operator call. · Severity: high (gateway down, pre-dates this plan) · Next touch: operator runs `openclaw doctor --fix`, then `deploy.sh --probe`.
- **2026-09-21 · Ollama Metal backend wedge (recurrence)** · During the first deploy pass the qwen3:8b runner answered every request with an empty malformed body; Ollama's server.log showed `ggml_metal_graph_compute: backend is in error state from a previous command buffer failure` on every call. Killing the `llama-server` subprocess recovered it (Ollama respawns a fresh runner). Same failure family as the 27-day hang recovered 2026-08-31; nothing probes for it, so the daemon silently falls back to regex extraction for as long as it lasts. · Severity: medium · Next touch: a watcher probe that issues a tiny generate and alerts on a non-JSON or `done:false` reply.
- **2026-09-26 · knowledge MCP server never starts from `.mcp.json` (`lib/mcp-knowledge/server.mjs` entrypoint guard)** · `.mcp.json` launches the server through `~/.openclaw/workspace/lib`, a symlink to the checkout; the entrypoint check (db94e64, 2026-09-06) compares the module's resolved URL with `argv[1]` as given, the two differ, so `main()` never runs and the process exits 0 with no output. Every Claude Code session on the node on 2026-09-26 logged `knowledge (CONNECTION_CLOSED)`; launched by its real path the same file starts and indexes. So none of this plan's MCP surface (`path_prefix`, `knowledge_tree`, `directory_overview`, `search_directories`) reaches a session, and `directory_summaries` has not updated since the 2026-09-21 probe pass. `workspace-bin/web-fetch.mjs` carries the same check. · Severity: high (the tool surface Blocks 1–2 feed is down on the node) · Next touch: a server.mjs step whose Verify is a session connecting to `knowledge` on the node.
- **2026-09-26 · scoped search past the sqlite-vec k ceiling (`lib/mcp-knowledge/core.mjs` `semanticSearch`/`findRelated`)** · With `VEC_K_MAX` the sparse-subtree fallback no longer throws, but it only sees the 4096 nearest chunks, and the node holds 8,839. A `path_prefix` whose documents all rank past the 4096th neighbour returns no hits even though the subtree has documents — an empty answer where the old code threw. Reproduced on 4,202 chunks: a subtree at rank ~501 returns its documents, one at rank ~4,201 returns `[]`. · Severity: medium (narrow prefix + off-topic query on the node) · Next touch: whoever next scopes knowledge search.
- **2026-09-26 · analysis wait timer outlives the call (`lib/ollama-queue.mjs` `requestAnalysis`)** · The timer raced against an analysis job stays armed after the job wins, so a short-lived process that called `generateAnalysis` cannot exit until the full wall elapses. With the directory summaries' 120 s batch wall, `probe.mjs` (deploy.sh step 4) can sit up to two minutes after its last LLM call; the directory-summaries test shortens the wall for the same reason. Long-running daemons are unaffected. · Severity: low · Next touch: the next ollama-queue step.
- **2026-09-27 · unscoped knowledge queries past the sqlite-vec k ceiling (`lib/mcp-knowledge/server.mjs` `semantic_search`/`find_related`)** · The `VEC_K_MAX` cap covers only the path-scoped fallbacks. The tools pass the caller's `limit` straight through, so an unscoped `semantic_search` with `limit` above 4096, or `find_related` with `limit` above 1365 (it asks for three times the limit), still throws. Found by the PR #29 review. · Severity: low (needs an unusually large limit) · Next touch: whoever next scopes knowledge search.
- **2026-09-27 · unparseable model answers in directory summaries (`lib/mcp-knowledge/directory-summaries.mjs`)** · A model answer that is `mode:'llm'` but does not parse (garbage, empty content, `{}`) never marks the model unusable for the pass. So on every pass each deterministic row is retried, spending the whole per-pass LLM budget. `stats.upgraded` counts those attempts as upgrades even though no row became `llm`. The review measured 20 model calls per unchanged pass, `llm=0`, `upgraded=20`. `probe.mjs` grades 2.2 PASS when `upgraded` equals the call count, so a wedged model can pass it. · Severity: medium (silent Ollama load and a false 2.2 signal) · Next touch: the step that re-closes 2.2.
- **2026-09-27 · MCP handshake waits for the full index pass (`lib/mcp-knowledge/server.mjs` `main`)** · The stdio transport connects only after the engine's initial index pass, which includes up to 20 LLM directory calls at about 30 s each on the node. Once the server starts through the symlink, a session's `initialize` can be held for minutes: at least one new note after days offline already forces a pass. The client may time out the handshake instead. Every session also spawns its own server over the same `.knowledge.db`. · Severity: medium (it will surface as soon as the 2026-09-26 guard entry is fixed) · Next touch: the server.mjs step whose Verify is a session connecting to `knowledge`.
- **2026-09-27 · deploy.sh grades 4.1 on configuration alone (`memory-plan/plans/openviking-adopt/deploy.sh` step 5)** · 4.1 is recorded PASS when `plugins.slots.contextEngine` names the plugin, while the row's Verify requires a `memory.injected` event with `frontend: "openclaw-context-engine"`. A config string proves neither plugin load nor injection, so the next run could produce "evidence" that closes 4.1 without a gateway turn. Found by the Codex node audit (2026-09-26). · Severity: medium · Next touch: 4.1.
- **2026-09-27 · context-engine compaction ownership (`packages/openclaw-memory-context-engine/context-engine.js`)** · The engine declares `ownsCompaction: true`, yet its `afterTurn` is empty and `compact` only delegates to the runtime. The installed OpenClaw docs say `true` disables Pi's built-in in-attempt auto-compaction and that delegating engines should declare `false`. Pre-prompt overflow safeguards and manual/overflow `compact()` remain. Its token-budget estimate also counts only string/text parts, so tool-call arguments, images and thinking blocks count zero. Found by the Codex node audit (2026-09-26); latent until the slot is selected. · Severity: medium when activated · Next touch: 4.1, before the slot is set on the node.
